# Harness 工程

> **Agent = Harness + LLM**
>
> LLM 提供智能。Harness 提供可靠性。两者结合，才构成一个生产级 Agent。

## 这个模块教什么

传统软件工程有测试、CI/CD、监控——这些是质量基础设施。Agent 工程同样需要自己的质量基础设施，这就是 **Harness**（测试线束）。

没有 Harness，你只有一个 Prompt。有了 Harness，你才有一个可部署、可回归、可演进的 Agent 系统。

Harness 不是"可选的测试套件"，它是 Agent 系统的核心架构组件。就像你不会把没有测试的代码部署到生产环境一样，你也不应该把没有 Harness 的 Agent 投入使用。

## 核心思维转变

从传统测试到 Harness 测试，需要转变三个核心认知：

| 传统测试 | Harness 测试 |
|---------|-------------|
| 验证确定性逻辑 | 验证概率性输出 |
| 期望精确匹配 | 期望语义合理 |
| Mock 函数返回值 | Mock 整个 AI API |
| 通过/失败二元判断 | 质量评分连续度量 |

这个转变不是技术细节的差异，而是思维模式的根本变化：你不再是"代码是否做对了"，而是"AI 的输出是否足够好"。
